# Gold-standard Grafana dashboards — built from the PROD export, for every environment

2026-08-17. Source of truth: the raw PROD Grafana export (`Export-GrafanaContent 1.1.0`, 27 dashboards,
4 folders, 26 scrape targets, 338 metric names, 13 legacy alert definitions) plus the discovery packages
for the APPMON/APPOPS boxes. Everything here was generated by `gold-dashboards/build/build.py`, imported
into a Grafana 10.4.19 with `Import-GrafanaContent.ps1`, and rendered against a synthetic 10-host
Windows fleet (Prometheus 3.5, both `wmi_*` and `windows_*` hosts) — 257 PromQL expressions, 0 errors,
every dashboard screenshotted with data.

## What you are getting

| Item | Where | What it is |
|---|---|---|
| 13 dashboards, 5 folders | `gold-dashboards/<folder>/*.json` + `manifest.json` | The gold set. Same JSON for CRE, SYS, STG, PROD |
| Import script | `Import-GrafanaContent.ps1` | Creates folders, upserts by uid, sets home, archives old, imports alert rules; `-WhatIf`; token or admin/password |
| Alert rules | `gold-dashboards/alerting/gold-alert-rules.json` (+ README) | 16 unified-alerting rules = the 13 legacy alerts, environment-agnostic, + 5 monitoring-of-monitoring rules |
| Generator | `gold-dashboards/build/build.py`, `lib.py`, `build_alerts.py`, `validate.py` | Regenerate after any change; `validate.py` evaluates every expression against a Prometheus |

**Import order:** CRE (`SRVCRE1APPOPS01:9091`) → look at it for a day → SYS → STG → PROD. Nothing is deleted
anywhere; PROD's existing dashboards keep working side by side until you archive them.

```powershell
# 1. dry run
.\Import-GrafanaContent.ps1 -Url http://srvcre1appops01:9091 -Credential (Get-Credential admin) -WhatIf
# 2. real, and make Monitoring Home the landing page
.\Import-GrafanaContent.ps1 -Url http://srvcre1appops01:9091 -Credential (Get-Credential admin) -SetHome gs-home
# 3. later, PROD: same command; then retire the superseded originals (moved to a "_Retired" folder, not deleted)
.\Import-GrafanaContent.ps1 -Url http://10.1.24.217:9091 -Token glsa_… -ArchiveOld OoYjJw-iz,P6vQvbLmz,o33aObLik,vPlc55Cik,sdlC-3-ik,7aEnmDfmk,VQGi7l-ik,DWReBQ-ik,efsv851ssfwu8e,PRipjDdHk
# 4. once unified alerting is switched on (see "Alerting"): the rules
.\Import-GrafanaContent.ps1 -Url http://… -Token glsa_… -Only none -ImportAlertRules
```

The only thing the script needs on the target is a Prometheus datasource (any name; the dashboards bind
to it through the `${DS_PROMETHEUS}` variable) and an Admin token or admin credentials.

## 2. Enriched — the design rules every gold dashboard follows

* **Environment-agnostic.** `Prometheus` (datasource variable) + `Environment` (`label_values(up{job!="prometheus"}, Environment)`,
  multi, All → `.+`). No datasource UID, hostname, environment or port literal appears in any JSON file.
  Import the same file into CRE and PROD; only the data changes.
* **Dual metric names.** Helper `M("cpu_time_total", sel)` expands to `(wmi_cpu_time_total{sel} or windows_cpu_time_total{sel})`;
  renamed families add the 0.31 name too (`os_physical_memory_free_bytes` → `windows_memory_physical_free_bytes`,
  `cs_physical_memory_bytes` → `windows_memory_physical_total_bytes`, `os_virtual_memory_bytes` → `windows_memory_commit_limit`,
  `os_paging_*` → `windows_pagefile_*`, `os_processes` → `windows_system_processes`, `cs_logical_processors` →
  `windows_cpu_logical_processor`, `system_system_up_time` → `windows_system_boot_time_timestamp_seconds`).
  PromQL `or` de-duplicates on identical label sets (metric name excluded), so a host is never counted twice.
  The Self-Health dashboard has a "metric families present" table that tells you which names are live on any Prometheus.
* **Core panels only**: timeseries, stat, gauge, bargauge, table, state-timeline, text, row, alertlist, dashlist. Nothing to install, nothing Angular.
* **Drill-down everywhere.** Every server name in every table links to *Server Detail* with the environment and time range carried across; every dashboard has a "Gold-standard dashboards" dropdown (tag `gold-standard`).
* **Thresholds are visible.** Every panel that corresponds to an alert draws the alert threshold as a dashed line and has a "breaching now" stat next to it.
* **Freshness is a first-class signal.** Every feeder task's `*_timestamp` metric and every `.prom` file's mtime is on a panel with a 30/60-min or 1h/1d threshold — the class of failure that let a feed die silently for six years.
* **Cheap by default.** Heavy panels (tile wall of ~5,900 Phoenix checks, top-20 cardinality) sit in collapsed rows; the fleet views aggregate on the Prometheus side and use instant queries for tables.
* **Stable uids** (`gs-*`) and stable folder uids, so re-importing is an idempotent upsert and version history accumulates in Grafana.

## 4. Other improvements found on the way (not dashboards)

**Alerting (the big one).** PROD runs *legacy* alerting: 2 e-mail channels ("Ops Team" is DEFAULT, so
every one of the 13 alerts — including the four titled "test alert" — mails the ops DL), 8 legacy alert
rules, 13 panel definitions. Grafana 11 deletes legacy alerting outright, so this must move before any
Grafana upgrade. Grafana 10.4 has the *upgrade preview* (Alerting → Upgrade) that converts channels →
contact points and panel alerts → rules without switching yet; do that first, review, then set
`[unified_alerting] enabled = true` / `[alerting] enabled = false` and restart. After the switch, import
`gold-alert-rules.json` (16 rules, one alert instance per Environment/instance/queue…), point the default
notification policy at the migrated "Ops Team" contact point, and archive the legacy alert dashboards.
Rule-level notes: Phoenix jobs `for` 10m → consider 15m; the generic "auto service not running" rule ships
paused until an exclusion list exists; OPA/Kofax rules use `NoData = NoData` so environments without those
roles stay quiet.

**Prometheus configuration on each APPOPS.** (a) Add a `role` label to file_sd entries (comma list) in
addition to the `Kofax="true"` flags — the flags work but a label *name* per role can't be enumerated by a
variable; the gold set carries a fixed role list because of it. (b) Add a `host` label via
`relabel_configs` (`__address__` minus port) so legends stop showing `:9182`. (c) The `alerting:` block has
an **empty** alertmanager list (the earlier discovery finding "alertmanager:9093 does not resolve" was a
commented-out line — fixed in discovery 0.11.1); Prometheus-side alerting is not used at all, Grafana is
the only alerting engine. (d) `srvtrnwebiis05/07` are DNS-dead targets still in file_sd — remove.
(e) Retention is 15d — capacity/days-to-full and week-on-week comparisons want 30–90d; the TSDB is small
once the service metrics are trimmed. (f) `wmi` job label — the gold set assumes `job!="prometheus"` for
exporter targets; keep that true in the lower environments.

**Cardinality.** `wmi_service_status` (50,688 series), `wmi_service_state` (33,792), `wmi_service_start_mode`
(21,120) are 88 % of PROD's ~120k series. `service_status` doesn't exist in windows_exporter 0.31; add the
`collector.service.include` regex from EXPORTER-WS2025-BUILD.md and the estate drops to a few thousand
series, scrapes get faster (the service collector is the slowest on every host — Self-Health shows it).

**Grafana hygiene.** Remove unused plugins (`blackmirror1-statusbygroup-panel`, `btplc-status-dot-panel`,
`snuids-trafficlights-panel`, `vonage-status-panel` — all unsigned or Angular; nothing in the gold set
needs them); the `alertmanager` datasource and `DocProd - uksombudsmanProdDocProd` (Azure Monitor)
datasource are referenced by nothing; the `test` folder and `General Alerting Alerts - febdb…` auto-folder
can go after cutover; per-user dashboard Admin permissions (three named users) should become team/role
permissions; org name is "Financial Ombudsman Service" in PROD and "Main Org." elsewhere — harmless.
`grafana-image-renderer` is installed (fine on 10.x, dropped in 13 — see UPGRADE-PATH.md).

**Intelligent Automation folder.** Twelve near-duplicate MSSQL dashboards (Documents Processed v1/v2,
ErrorsLogs v1/v3/v31/Business/Red-Date-Filter/v2/v3/v4/Trend/Test) created in the last five weeks by one
author, all "no variables". Suggest that owner keeps *ErrorsLogs Business v4* + *Documents Processed v2*
and deletes the rest, adds a date-range variable, and moves them to a folder the IA team owns. Not
touched by the import.

**Feeder tasks.** `appinsights_metrics.prom` (dead since 2020) is still exposed by SRVFOSAPPMON01 — delete
the file on the old box; the new box never gets it (STANDUP-NEW-APPMON.md step 4). `AdhocServiceStatusExporter`
last wrote on 1 May in CRE — fix-or-retire.

**Change controls.** The gold set does not need a change of its own beyond a low-risk "add dashboards"
entry: it adds folders and dashboards, deletes nothing, and can be removed by deleting the five
`Monitoring*` folders. The alerting cutover *is* a change (Grafana restart, notification path changes) —
put it in CR-4 (Grafana upgrade tranche) or its own CR.

## 5. New dashboards worth building next (data is already there, or one collector away)

Already scraped today — build from the same generator in an afternoon each:

1. **Environment comparison** — the same KPI row for every Environment side by side (targets up, CPU/mem
   averages, Phoenix backlog, feed ages) using `repeat` by `Environment`. Immediately shows CRE ≠ PROD
   drift after the migration.
2. **Business hours SLO view** — Phoenix jobs "Waiting" p95 during 08:00–18:00, MSMQ backlog minutes-over-500
   per day, REST endpoint availability % (`avg_over_time(intergation_rest_service_status[1d])`), Adhoc
   service success %. Uses only existing series; gives management one number per service per week.
3. **Phoenix throughput** — `increase(phoenix_system_jobs{StatusCodeName="Succeeded"}[1h])` and Failed per
   hour → jobs/hour, failure rate, and a "time to drain the backlog at current rate" stat.
4. **IIS per-site deep dive** — repeat panels by `site`: requests, bytes, connections, anonymous vs
   authenticated users, cache hit ratios (`wmi_iis_*_cache_hits_total / _queries_total`), worker threads
   busy — 100+ IIS metrics exist and only 5 are used today.
5. **Kofax batch pipeline** — service state + disk busy + CPU on the KCS/capture boxes is there; add a
   feeder `.prom` from the Kofax database (batches in queue / batches errored per module) and it becomes a
   real pipeline view. Same pattern as PhoenixMetricsGatherer.
6. **Capacity forecast** — `predict_linear` on disk, memory, Phoenix backlog and SharePoint folder counts
   at 30/60/90 days (needs retention ≥ 30d to be meaningful).

One exporter collector away (windows_exporter 0.31.8 has them; wmi_exporter 0.4.3 didn't):

7. **Scheduled-task health** — enable the `scheduled_task` collector on the APPMON boxes and you get
   `windows_scheduled_task_last_result` / `_state` / `_missed_runs` for every feeder task. This is exactly
   what the change controls ask you to prove by hand today ("LastTaskResult 0, fresh .prom") — as a
   dashboard and an alert. Strong recommendation for the new CRE box tomorrow.
8. **Time sync** — `time` collector (`windows_time_ntp_client_time_source_*`, clock offset). D365/OPA auth
   tokens fail silently when a box drifts; cheap to collect.
9. **OS / patch level** — `os` collector's `windows_os_info{version,build_number}` on 0.31 gives a
   fleet table of Windows build numbers: the migration tracker at OS level (2012 → 2025) and a patch-level
   drift view afterwards.
10. **Print server** — `printer` collector on `vmprdappprn02` (it is a print server in the RestServicesD365
    role set): jobs queued, printer status.
11. **SQL Server** — `mssql` collector on the four SQL endpoints found in the endpoint sweep: connections,
    batch requests, buffer cache hit ratio, blocked processes, log space.
12. **TCP / logon** — `tcp` (connections established/reset per state) and `logon` (session counts) collectors
    for the web tier; helps triage "IIS slow" complaints.

Each is a `build_xxx()` function in `build.py` away, and inherits every design rule automatically.

## What was verified, and what still needs the real estate

* All 257 dashboard expressions and 16 rule expressions parse and return data on Prometheus 3.5 with the
  synthetic fleet; the import ran clean against Grafana 10.4.19 with token and with admin/password; the
  rules were provisioned and evaluated (`health: ok`) on that Grafana; every dashboard was rendered
  headlessly and inspected (screenshots delivered alongside — synthetic data, nothing from PROD).
* Still to confirm on the first real WS2025 box (CRE, tomorrow): the exact windows_exporter 0.31.8 names
  for the renamed memory/system metrics — the "Metric families present" table on Self-Health shows which
  of the alternatives are live; if one is wrong it is a one-line change in `lib.RENAMED`, rebuild, re-import.
* Table panels rely on Grafana's `merge` transformation, which needs identical label sets across the
  panel's queries — the generator enforces `by (Environment, instance, …)` on every table query for that
  reason; if you add a query to a table by hand, keep that rule.
* Legends show `host:9182` until the `host` relabel (§4) is added; harmless.
